# Моніторинг живлення домашнього Linux-сервера

Python 3.11+. Скрипт кожні 10 секунд читає стан мережевого живлення та батареї й надсилає сповіщення Telegram. При заряді **5% або нижче на батареї** бот лише попереджає адміністратора. Вимкненням при **4%** займається окремий systemd-сервіс Linux Mint. Кнопка «🔋 Поточний заряд» та команди `/battery` і `/status` дозволяють перевірити поточний стан.

## Налаштування .env

Виконуйте команди з директорії `server-power-monitor`. Скопіюйте `.env.example` у `.env` і заповніть `BOT_TOKEN`, `ADMIN_CHAT_ID` та `USER_CHAT_ID`. Токен видає Telegram-бот @BotFather. Для особистих сповіщень спочатку відкрийте свого бота в Telegram і натисніть Start. Бот повинен мати доступ до вказаного чату.

```dotenv
BOT_TOKEN=ваш_токен
ADMIN_CHAT_ID=chat_id_адміністратора
USER_CHAT_ID=chat_id_користувача
TEST_MODE=false
```

- `ADMIN_CHAT_ID` — детальні сповіщення: запуск моніторингу/сервера, зникнення/повернення живлення із зарядом, сповіщення на 80%, 60%, 40%, попередження 30% і 15%, критичне попередження при 5%.
- `USER_CHAT_ID` — короткі сповіщення про запуск, зникнення та відновлення світла, без автоматичних попереджень про заряд. Після відновлення світла обидва чати отримують тривалість відключення. Кнопка й команди перевірки заряду доступні також цьому чату. Порожнє значення вимикає додаткового отримувача.
- Кожна змінна містить один ID особистого чату або групи. Обидва користувачі мають спочатку натиснути Start у боті; для групи додайте до неї бота. Якщо ID однакові, один чат отримуватиме і детальне, і коротке повідомлення.
- При оновленні перейменуйте старий `CHAT_ID` на `ADMIN_CHAT_ID` та додайте `USER_CHAT_ID`. Старий `CHAT_ID` ще підтримується як запасний варіант, коли `ADMIN_CHAT_ID` порожній. Після редагування перезапустіть сервіс.

`.env` виключений із Git. Він завантажується з директорії `bot.py`; вже задані змінні середовища мають пріоритет. Не публікуйте токен.

## Кнопка заряду та команди

Під кожним повідомленням бота є кнопка **«🔋 Поточний заряд»**. Натисніть її або надішліть `/battery` чи `/status`, щоб отримати свіжий вимір:

```text
🔋 Поточний заряд: 62%
⚡ Живлення від батареї
🖥 Сервер працює: 1 год 1 хв 1 с
```

Час роботи сервера читається з `/proc/uptime` на Linux. Якщо датчик недоступний, бот пише, що заряд/живлення невідомі. `/start` та `/help` показують інструкцію з кнопкою. Для першої перевірки після оновлення надішліть `/start`.

Бот відповідає тільки у чатах, указаних у `ADMIN_CHAT_ID` та `USER_CHAT_ID`. Для груп це означає доступ усіх учасників цієї групи. Кнопка працює і в групах; команди можна надсилати як `/battery@імʼя_бота`.

Отримання команд працює через Telegram `getUpdates` в окремому потоці та не блокує цикл перевірки батареї. Запускайте лише один екземпляр цього бота з одним токеном. Для цього токена не має бути активного webhook: Telegram не дозволяє поєднувати його з `getUpdates` ([документація Telegram](https://core.telegram.org/bots/api#getupdates)).

## Запуск після вимкнення та тривалість відключення

Початок відключення, пройдені пороги батареї та ідентифікатор завантаження Linux зберігаються у **`monitor-state.json` поруч із `bot.py`**. Початок відключення записується до сповіщень через тимчасовий файл та атомарну заміну, щоб пережити вимкнення сервера. Користувач сервісу повинен мати право запису до цієї директорії. Файл стану й тимчасовий файл виключені з Git; зберігайте їх під час оновлення.

Коли сервер автоматично ввімкнеться після повернення електрики, адміністратор отримає, наприклад:

```text
🟢 Сервер увімкнувся
🔌 Сервер працює від мережі
🔋 Заряд: 8%
✅ Живлення відновлено
⏱ Від зникнення живлення до запуску моніторингу: приблизно 3 год 12 хв 4 с
```

Другий чат отримає коротке повідомлення про повернення світла, роботу сервера та той самий час. Цей час включає завантаження ОС і запуск сервісу: точний момент повернення електрики вимкнений сервер виміряти не може. Для розрахунку через перезапуск потрібен правильний системний час Linux.

Ідентифікатор `/proc/sys/kernel/random/boot_id` відрізняє перезавантаження сервера від перезапуску самого сервісу. При перезапуску сервісу надсилається «Моніторинг запущено». Якщо збереженого початку відключення немає, бот повідомляє поточний стан без твердження про відновлення світла чи вигаданої тривалості. Якщо моніторинг почався вже без світла, тривалість позначається як «щонайменше … (від запуску моніторингу)».

Якщо під час запуску ще немає інтернету, стартові повідомлення залишаються у файлі стану й повторно надсилаються після появи звʼязку. Успішно надіслані отримувачу повідомлення прибираються з черги.

## Windows / PyCharm: тестовий режим

У PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

У `.env` встановіть `TEST_MODE=True`, потім запустіть:

```powershell
.\.venv\Scripts\python.exe bot.py
```

У PyCharm виберіть інтерпретатор `.venv\Scripts\python.exe` та запустіть `bot.py`. Можна також задати `TEST_MODE=True` у змінних середовища конфігурації запуску.

Тестовий режим не читає `/sys` і не змінює файл стану. Бот не виконує команд вимкнення в жодному режимі. Якщо токен або ID отримувача порожні, відповідне повідомлення виводиться лише в лог. Якщо токен та ID заповнені, повідомлення дійсно надсилається в Telegram і доступні команди. Для повністю локального тесту залиште `BOT_TOKEN` порожнім; задайте тестові `ADMIN_CHAT_ID=123` та `USER_CHAT_ID=456`, щоб бачити в логах обидва стартові повідомлення.

Сценарій `TEST_SCENARIO` в `bot.py`: мережа → батарея → 80% → 60% → 40% → 30% → повтор 30% → 15% → 7% → 5% (критичне попередження) → повтор 5% → повернення мережі → нове відключення при 30% → мережа. Один крок кожні 10 секунд; після завершення зберігається останній стан. Зупинка — Ctrl+C. Сценарій можна змінювати.

## Linux Mint

```bash
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

Потрібен Python 3.11 або новіший; якщо модуль venv відсутній, встановіть пакет venv для своєї версії Python. Заповніть секрети в `.env`, встановіть `TEST_MODE=false` і запустіть:

```bash
.venv/bin/python bot.py
```

Джерела даних:

- `/sys/class/power_supply/AC/online`: `1` — мережа, `0` — батарея.
- `/sys/class/power_supply/BAT0/capacity`: заряд від 0 до 100.

Перевірка вручну:

```bash
cat /sys/class/power_supply/AC/online
cat /sys/class/power_supply/BAT0/capacity
```

На іншому обладнанні назви можуть відрізнятися. За потреби змініть `AC_PATH` і `BATTERY_PATH` у `bot.py`.

## Критичний заряд: попередження при 5%, вимкнення при 4%

При заряді **5% або нижче на батареї** бот надсилає лише в `ADMIN_CHAT_ID` таке повідомлення:

```text
Критичний заряд батареї 5%. Автоматичне вимкнення сервера відбудеться при 4%
```

Це попередження надсилається один раз за період роботи від батареї, зокрема якщо вимір одразу показав менше 5%. Подальше падіння до 4% і нижче не викликає повторних попереджень або команд від бота. Повернення мережевого живлення скидає прапорці попереджень.

**Вимкнення при 4% виконує окремий systemd-сервіс Linux Mint**, який налаштовується незалежно від бота. Бот не запускає `shutdown`, `sudo` чи інші команди вимкнення й не керує цим окремим сервісом. `server-power-monitor.service` у цьому репозиторії запускає лише моніторинг і Telegram-сповіщення.

Для роботи бота дозвіл sudo на вимкнення більше не потрібен. Старі інструкції з надання боту такого дозволу до цієї версії не застосовуються.

## Автозапуск через systemd

Відредагуйте `server-power-monitor.service`: замініть `YOUR_USER`, `WorkingDirectory` та шляхи в `ExecStart` на реальні абсолютні шляхи Linux. Для шляхів із пробілами візьміть значення `WorkingDirectory` та кожен шлях у `ExecStart` у подвійні лапки. Сервіс використовує Python із `.venv`; `.env` читає сам скрипт.

```bash
sudo cp server-power-monitor.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now server-power-monitor.service
sudo systemctl status server-power-monitor.service
journalctl -u server-power-monitor.service -f
```

`Restart=always` перезапускає процес після завершення з паузою 10 секунд. Для зупинки:

```bash
sudo systemctl stop server-power-monitor.service
```

Після зміни `.env` перезапустіть сервіс через `sudo systemctl restart server-power-monitor.service`.

При оновленні чинної інсталяції замініть `bot.py`, зберігши `.env` та `monitor-state.json`, і перезапустіть сервіс. Залежності й змінні `.env` залишилися сумісними. Перевірте `journalctl -u server-power-monitor.service -n 50 --no-pager`, потім надішліть боту `/start` і натисніть кнопку заряду. Вимкнення при 4% має бути налаштоване в окремому systemd-сервісі Linux Mint.

## Поведінка та перевірка логіки

Автоматичні тести (без звернень до Telegram та без реального вимкнення):

```bash
python -m unittest -v
```

Використовуйте Python із встановленими залежностями: `.venv/bin/python` на Linux або `.\.venv\Scripts\python.exe` на Windows. GitHub Actions повторює тести на Linux і Windows з Python 3.11–3.13 та перевіряє синтаксис systemd-сервісу, не запускаючи його.

- Після запуску моніторингу надсилається поточний стан. Під час подальшої роботи сповіщення про зникнення/повернення мережі надсилаються лише при зміні AC.
- Пороги перевіряються як `<=`, тому пропуск точного відсотка не завадить попередженню. При різкому падінні або запуску з низьким зарядом надсилається тільки найтерміновіше попередження.
- У межах одного запуску тривалість вимірюється монотонним годинником. Через перезапуск початок відключення відновлюється із системного часу, тому тривалість позначається як приблизна. Якщо після перезапуску сервер ще на батареї, подальше вимірювання знову використовує монотонний годинник. Точність також обмежена інтервалом опитування й затримками запитів.
- Кожен поріг спрацьовує один раз за період роботи від батареї, у тому числі після перезапуску сервісу завдяки файлу стану. Повернення мережі скидає прапорці. Помилка читання/запису стану логується; моніторинг продовжує працювати, але збереження тривалості й прапорців тоді не гарантується.
- При помилці читання AC ітерація пропускається. Якщо заряд невідомий, зміни AC все одно повідомляються, але попередження про заряд пропускаються.
- Мережеві помилки та помилки Telegram логуються, процес продовжує роботу. Запити мають timeout. Стартові повідомлення зберігаються для повторного надсилання; звичайні сповіщення про переходи та пороги черги не мають і при збоях можуть бути втрачені. Окремий сервіс вимкнення працює незалежно від Telegram.
- `process_reading(MonitorState(), ac, battery)` дозволяє перевіряти переходи окремо від циклу. У тестах підміняйте `send_telegram_message` через `unittest.mock`; функції читання та Telegram також можна перевіряти окремо. Тести перевіряють точний текст попередження при 5%, надсилання лише адміністратору, відсутність повторів і викликів системних команд при 5%, 4% та 0%.

systemd запускає моніторинг після завантаження ОС, але сам не вмикає вимкнений ноутбук після повернення електрики — це залежить від налаштувань BIOS/UEFI та обладнання.
